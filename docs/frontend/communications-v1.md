## Implemented experience

Staff management remains at `/announcements` and `/announcements/[id]`. The directory retains bounded server-backed search, lifecycle/audience/target-type filters and pagination. It displays supported latest title/body preview, lifecycle, latest Version, updated time and open action. It does not fetch each row's targets or Versions to manufacture richer columns or totals.

Creation uses the existing protected-focus dialog and React Hook Form/Zod validation. The author supplies title, plain text or safe HTML, and sees a live preview using `AnnouncementBody`. Plain text is escaped; HTML uses the existing shared sanitize-html allowlist. Submission retains inputs on failure, creates a Draft with Version 1, then opens detail for explicit target and file preparation. No separate wizard or rich-text SDK was added.

Detail leads with the exact current content Version, lifecycle and freeze guidance. Current targets precede files in document order. School Admins use supported School/Class targets; Teachers remain authored-announcement and active-assignment scoped, with Class-only choices. Each target explicitly selects audience and active Academic Year, plus an eligible Class where required. Existing selections are inspectable and obvious exact duplicates are withheld from submission; server validation remains authoritative. The UI invents neither recipient identities nor counts.

The all-publication read is used to determine whether the latest Version has ever had an intent. Any intent freezes that Version's targets and files, including a cancelled intent. Failed detail, Version, publication-history, Year/Class or required Teacher-scope reads show controlled recovery instead of editable controls. Cancellation does not restore mutability. A correction opens a blank new-content form; the new Version starts with explicitly selected fresh targets and its own files. Historical content, targets, attachments and publication associations are not silently copied or rewritten.

Publish-now and initial scheduling use the current exact Version. Their review repeats its title, safely rendered body, explicit audience/Year/Class targets and READY filenames. Confirmation requires successful target/file reads, at least one target and every returned file being READY. Failed supporting reads expose retry. The content preview in review scrolls after 240px rather than forcing the dialog footer out of reach. Publication success and asynchronous Notification processing remain distinct.

Scheduling accepts a School-local wall time, shows the current School timezone, validates through the existing timezone-aware schema and converts through `schoolWallTimeToInstant`. Pending-intent rescheduling keeps the exact publication/Version association. Reschedule and cancel actions appear only for SCHEDULED rows; cancellation requires confirmation, remains visible as CANCELLED history and preserves server race/conflict handling. Version and publication histories remain separate paginated records with actual Version associations and School-local timestamps.

Private attachments remain exact-Version scoped. The UI exposes PDF/PNG/JPEG, 2 MiB per file and ten active files per Version; it supplies an explicit native file input and upload action, byte size, readiness and permitted logical removal confirmation. Downloads are offered only for READY files through existing authorized endpoints. The selected upload retains its idempotency request ID. Pending work blocks duplicate actions. A non-READY upload response or `FILE_RECONCILIATION_REQUIRED` latches an uncertain state in that mounted attachment component, disables further file mutations and shows refresh/operator guidance. It does not claim successful upload or automatically retry an uncertain operation. Publication readiness independently checks the authoritative attachment list. Private storage, MIME/signature checks, authorization and reconciliation remain server responsibilities; the UI does not promise malware scanning.

Received Announcements remain separate at `/announcements/inbox` and `/announcements/inbox/[id]`. Teacher and Parent recipients see the immutable exact publication, Version, body, School-local time and authorized READY files. These surfaces contain no management or write controls. Denied/unavailable publications show controlled guidance without exposing private files.

Personal Notifications remain at `/notifications`. Persisted unread count, read-state/source filters and pagination use existing APIs. Rows distinguish unread through a dot, tonal treatment and explicit text. Detail preserves the stored title/body, source, received time and read state. Opening detail performs no mark-read mutation. Mark-one and mark-all use the existing bodyless POST operations and server-owned timestamps, then refresh relevant cached state. There is no mark-unread, archive, delete or Notification creation control.

Notification rows and detail format received timestamps with `formatSchoolInstant` and the current School timezone. Source navigation accepts only a server-provided relative destination matching the supported published Announcement or published Result/history route shape. A missing or inaccessible destination preserves the message and shows unavailable guidance. The destination API still independently authorizes access. Communication query keys and school-switch clearing preserve current-School/current-User isolation; client visibility is not tenant authorization.
